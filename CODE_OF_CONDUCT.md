# Community conduct

Be respectful, discuss the work, and make it possible for others to contribute.
These standards apply to this repository's issues, pull requests, reviews and
other project-managed spaces.

Expected behavior:

- Give specific, reproducible feedback. Criticize an idea or implementation,
  not the person who proposed it.
- Welcome different backgrounds and experience levels. Respect names,
  boundaries and decisions to leave a conversation.
- Handle disagreements without insults, threats, discrimination, harassment
  or repeated unwanted contact.
- Never publish another person's private information, credentials, private
  keys or sensitive appliance data.

Maintainers may edit or remove harmful content, limit a discussion, reject a
contribution or restrict participation. Responses should be proportionate to
the behavior and its impact. A maintainer involved in a dispute should ask an
uninvolved maintainer to review it where one is available.

## Reporting

For a public violation, notify the repository maintainers with a link to the
content; do not copy abusive text or personal information into another public
thread. Use GitHub's **Report content / Report abuse** controls and check the
destination shown: **Report abuse** goes to GitHub; reporting directly to
maintainers is available only if the repository enables that option. Neither
establishes a separately monitored project mailbox. See
[GitHub's reporting instructions](https://docs.github.com/en/communities/maintaining-your-safety-on-github/reporting-abuse-or-spam).

No dedicated confidential project conduct mailbox or response-time commitment
is currently published. Do not put confidential details in an issue while
waiting for one. Security vulnerabilities and exposed credentials should use
the private route in [SECURITY.md](SECURITY.md).
